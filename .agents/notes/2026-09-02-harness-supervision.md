# Harness supervision

The board separates stopped execution from a completed objective. A nonblank idle session previously appeared in Done even when work had only paused or been cancelled. Goal complete now requires the current Harness goal projection to record completion. Pending input, running execution, errors, blocked goals, and queued work retain precedence. The unread-finish reminder remains a navigation fact, not completion evidence.

Goal phases and round usage come from the published `dsh-goal` client types. The import is erased at build time; the bundle neither mounts a goal service nor adds a browser external. An absent or cleared projection leaves ordinary sessions usable. An active goal does not imply armed continuation, and rounds used do not measure task completion.

Attention actions open the existing session so its interaction owner handles the current request. The board retains no answer callback or approval authority. Goal objectives and blocker explanations are visible on cards but excluded from the explicit export allowlist.

Runtime callbacks read one face and suppress unchanged lifecycle publications. Immutable snapshots retain unaffected entries, and memoized cards retain unchanged projections. A replaced face is rebound on list reconciliation; callbacks from detached faces and disposed sources have no effect. Snapshot copying and full-board projection still scale with session count; the runtime benchmark excludes rendering and network delivery.
